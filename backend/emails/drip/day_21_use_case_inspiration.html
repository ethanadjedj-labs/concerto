5 things power users do with Concerto.

Three weeks in, here's what we see from operators who get the most out of Concerto:

01

Overnight dependency upgrades

Run npm audit fix --force across 6 repos simultaneously, each in its own tmux session. Claude Code opens PRs, runs tests, and flags breakage. Wake up to a diff review, not a task list.

02

Persistent scraping pipelines

Set up a scraper, have Claude Code schedule it via cron, then check results the next day. Your Concerto environment keeps running after your claude.ai conversation closes — no timeouts, no cold starts.

03

Multi-file refactors with full grep context

Claude Code on a real shell runs rg, find, and sed across the whole codebase. Operators use this for API migrations where you need to touch 40+ call sites across a monorepo.

04

Local model inference via Ollama

Install Ollama in your Concerto environment, pull llama3:8b, and have Claude Code use it for fast local inference tasks — summarization, classification, extraction — without API costs or rate limits.

05

Database migrations with real-time validation

Run the migration, query the result set, validate row counts, and roll back if the delta is wrong — all in one Claude Code session. Your Concerto environment has full network access, so it can reach staging and production databases in the same session.

Which of these fits your workflow? Reply and tell us — the best use cases make it into our docs.
