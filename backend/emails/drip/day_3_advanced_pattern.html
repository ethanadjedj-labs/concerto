Try this: 3 sessions in parallel.

Most people run Claude Code one task at a time. With Concerto, your environment handles multiple concurrent sessions — each in its own tmux window, sharing the same filesystem and tools.

Here's a prompt pattern that spawns three independent workstreams and waits for all three before reporting results:

Start 3 background Claude Code sessions: 1. Session A: scan /tmp for files larger than 1MB, write results to /tmp/scan_a.txt 2. Session B: run `uptime && date` and write to /tmp/scan_b.txt 3. Session C: count lines in every .log file under /var/log (non-recursive), write to /tmp/scan_c.txt Run all three in parallel via tmux or background subshells. When all three finish, read and summarize all three output files.
Power tip: use tmux new-session -d -s <name> to keep each session independent. Concerto manages the orchestration; Claude Code handles the execution.

This pattern scales to real workloads: parallel test runs, multi-repo refactors, concurrent API migrations. Sessions share the filesystem so intermediate outputs flow naturally between them.
