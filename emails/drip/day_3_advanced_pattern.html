Try this: 3 sessions in parallel.

Most people run Claude Code one task at a time. With Concerto, your account handles multiple concurrent sessions — each in its own tmux window, sharing the same filesystem and tools.

Here's a prompt pattern that spawns three independent workstreams and waits for all three to finish before reporting results:

Start 3 background sessions: 1. Session A: scan /tmp for files larger than 1MB, write results to /tmp/scan_a.txt 2. Session B: run `uptime && vmstat 1 3` and write to /tmp/scan_b.txt 3. Session C: count lines in every .log file under /var/log (non-recursive), write to /tmp/scan_c.txt Run all three in parallel via tmux or background subshells. When all three are done, read and summarize all three output files.
Power tip: use tmux new-session -d -s <name> to keep each session independent. Claude Code manages the orchestration; Concerto handles the compute.

This pattern scales to real workloads: parallel test runs, multi-repo refactors, concurrent API migrations. The sessions share the filesystem so intermediate outputs flow naturally between them.
